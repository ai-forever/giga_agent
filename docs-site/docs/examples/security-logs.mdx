# Анализ логов безопасности

Этот пример показывает, как GigaAgent может помочь с первичным разбором логов: найти подозрительные события, сгруппировать их по источникам и подготовить рекомендации для администратора.

## Что показывает пример

- загрузку текстового файла с логами;
- поиск повторяющихся ошибок авторизации;
- группировку по IP, пользователям или времени;
- построение графиков активности;
- список защитных действий.

## Требования

- `giga-agent==0.1.9`;
- настроенный LLM connector;
- REPL/Python runtime;
- обезличенные или синтетические логи для публичной демонстрации.

## Возможности GigaAgent

- Files and artifacts;
- REPL/Python tools;
- регулярные выражения и табличная агрегация;
- summary с практическими рекомендациями.

## Пример промпта

```text
Я загрузил файл auth.log. Проанализируй попытки входа:
1. найди подозрительные IP и пользователей;
2. покажи часы с наибольшим числом ошибок;
3. выдели признаки brute-force;
4. предложи меры защиты;
5. сделай короткий отчёт для администратора.
```

## Ожидаемый результат

- таблица подозрительных источников;
- временное распределение событий;
- объяснение критериев подозрительности;
- рекомендации вроде rate limiting, fail2ban, MFA и ротации ключей.

## Как адаптировать

- Перед загрузкой удалите реальные IP, hostnames, usernames и внутренние пути.
- Для регулярного мониторинга лучше подключить SIEM/лог-хранилище через отдельный инструмент, а не загружать production-логи вручную.
- Попросите агента отделить факты из логов от гипотез.

## Ограничения

Это triage-сценарий, а не полноценный incident response. Финальные действия должен подтверждать ответственный администратор или security engineer.

## Галерея исторических прогонов

Для security-сценариев галерея не публикуется, пока скриншоты не будут полностью пересобраны на синтетических логах. Это снижает риск раскрыть реальные IP-адреса, hostnames или детали инфраструктуры из старых прогонов.
