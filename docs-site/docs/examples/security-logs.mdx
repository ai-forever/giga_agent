# Анализ логов безопасности

Этот пример показывает, как GigaAgent может помочь с первичным разбором логов: найти подозрительные события, сгруппировать их по источникам и подготовить рекомендации для администратора.

## Что показывает пример

- загрузку текстового файла с логами;
- поиск повторяющихся ошибок авторизации;
- группировку по IP, пользователям или времени;
- построение графиков активности;
- список защитных действий.

## Требования

- запущен GigaAgent;
- настроенное подключение языковой модели;
- доступна среда REPL/Python;
- обезличенные или синтетические логи для публичной демонстрации.

## Возможности GigaAgent

- файлы и артефакты;
- инструменты REPL/Python;
- регулярные выражения и табличная агрегация;
- краткая сводка с практическими рекомендациями.

## Пример промпта

```text
Я загрузил файл auth.log. Проанализируй попытки входа:
1. найди подозрительные IP и пользователей;
2. покажи часы с наибольшим числом ошибок;
3. выдели признаки перебора паролей;
4. предложи меры защиты;
5. сделай короткий отчёт для администратора.
```

## Ожидаемый результат

- таблица подозрительных источников;
- временное распределение событий;
- объяснение критериев подозрительности;
- рекомендации вроде ограничения частоты запросов, fail2ban, MFA и ротации ключей.

## Как адаптировать

- Перед загрузкой удалите реальные IP-адреса, имена хостов, имена пользователей и внутренние пути.
- Для регулярного мониторинга лучше подключить SIEM/лог-хранилище через отдельный инструмент, а не загружать боевые журналы вручную.
- Попросите агента отделить факты из логов от гипотез.

## Ограничения

Это сценарий первичной triage-оценки, а не полноценное реагирование на инцидент. Финальные действия должен подтверждать ответственный администратор или специалист по безопасности.

## Галерея исторических прогонов

Для сценариев безопасности галерея не публикуется, пока скриншоты не будут полностью пересобраны на синтетических логах. Это снижает риск раскрыть реальные IP-адреса, имена хостов или детали инфраструктуры из старых прогонов.
