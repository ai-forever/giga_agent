# Быстрый старт через Docker

Основной способ локальной установки GigaAgent — пакет из PyPI; он описан в разделе [Быстрый старт локально](./local.md). Обычно для первого знакомства достаточно установить пакет и запустить `giga_agent dev`.

Docker Compose нужен не для самого простого запуска, а для проверки более близкой к серверной схемы. Этот сценарий поднимает GigaAgent вместе с отдельными службами: nginx, PostgreSQL, Redis и Qdrant. Его стоит выбирать, если нужно проверить работу с постоянными данными, RAG, векторным хранилищем, сетевыми настройками или показать сервис как отдельное веб-приложение.

## Когда выбирать Docker Compose

Используйте этот путь, если нужно:

- проверить GigaAgent в окружении с отдельной базой PostgreSQL;
- проверить RAG и память с Qdrant;
- проверить работу через nginx на отдельном порту;
- подготовить демонстрационный или внутренний стенд;
- проверить сценарии, где агент управляет контейнерными изолированными средами.

Если нужно просто попробовать чат локально, используйте [установку из PyPI](./local.md): она быстрее и требует меньше инфраструктурных настроек.

## Что поднимается

`docker-compose.yml` собирает и запускает:

| Служба | Назначение |
|---|---|
| `nginx` | Отдаёт веб-интерфейс и проксирует запросы к серверной части. |
| `giga-agent` | Серверная часть GigaAgent и LangGraph API. |
| `giga-agent-postgres` | База данных приложения GigaAgent. |
| `langgraph-postgres` | База данных для LangGraph. |
| `langgraph-redis` | Redis для очередей, кэша и служебных блокировок. |
| `qdrant` | Векторное хранилище для RAG и памяти. |

Nginx публикуется на порту `8123`, поэтому после запуска интерфейс открывается по адресу `http://localhost:8123`.

## Минимальная подготовка

Скопируйте пример окружения:

```bash
cp .env.example .env
```

Минимально проверьте в `.env`:

```env
GIGA_AGENT_SECRET_KEY=<длинное-случайное-значение>
GIGA_AGENT_HOST_PROJECT_PATH=<абсолютный-путь-к-каталогу-проекта>
```

`GIGA_AGENT_SECRET_KEY` нужен серверной части для авторизации. Для общего или демонстрационного сервера задавайте своё длинное случайное значение.

`GIGA_AGENT_HOST_PROJECT_PATH` нужен только для сценариев с локальной Docker-изолированной средой. Если выполнение кода в контейнерах не используется, эту настройку можно отложить.

Ключи провайдеров моделей можно добавить после запуска через веб-интерфейс, как и при обычной установке из PyPI.

## Запуск

Из корня проекта выполните:

```bash
docker compose up --build
```

После старта откройте:

```text
http://localhost:8123
```

Альтернативно можно использовать команды из `Makefile`:

```bash
make build
make up
```

## После запуска

1. Войдите через веб-интерфейс.
2. Настройте коннектор и языковую модель.
3. Для RAG настройте векторные представления и проверьте Qdrant.
4. Для выполнения кода настройте изолированную среду и проверьте границы доступа к файловой системе.

## Важные ограничения

- Этот способ требует Docker и больше ресурсов, чем локальный запуск из PyPI.
- `docker-compose.yml` использует тома данных; при повторном запуске состояние может сохраняться.
- Контейнер `giga-agent` монтирует Docker-сокет хоста. Это удобно для локальных изолированных сред, но требует доверенной среды запуска.
- `docker-compose.dev.yml` предназначен для разработки. Не копируйте абсолютные пути из него без замены на свои.

Подробнее о настройках окружения см. [Конфигурация](../operations/configuration.md), о рисках выполнения кода — [Изолированная среда и безопасность](../operations/sandbox-security.md).
