# Чат и диалоги

Основной сценарий работы — отправить сообщение агенту и получить ответ по мере генерации. Веб-интерфейс обращается к серверу через адрес `/api`; маршруты GigaAgent обычно начинаются с `/api/agent`.

## Навигация

Основные разделы интерфейса:

- `/` — стартовый экран;
- `/threads/:threadId` — отдельный диалог;
- `/rag` — коллекции документов для RAG;
- `/memories` — долговременная память;
- `/settings` — настройки пользователя и провайдеров;
- `/admin-panel` — администрирование пользователей и групп.

## Что отправляется агенту

При отправке сообщения интерфейс может передать:

- текст пользователя;
- вложенные файлы;
- выбранные коллекции RAG;
- дополнительные MCP-инструменты;
- признак автоматического подтверждения действий.

Ответ приходит постепенно, поэтому интерфейс может показывать ход генерации, вызовы инструментов и их результаты.

## Остановка ответа

Пока агент отвечает, в интерфейсе доступна кнопка остановки. Она прерывает текущий запуск диалога; уже сгенерированная часть ответа сохраняется в истории, поэтому диалог не теряет контекст.

Остановка освобождает активный поток выполнения. Число одновременно активных диалогов на пользователя ограничено переменной `GIGA_AGENT_MAX_ACTIVE_THREADS_PER_USER` (см. [Конфигурацию](../operations/configuration.md)).

## Если сообщение не выполняется

Проверьте:

1. У пользователя выбрана языковая модель.
2. Провайдер модели доступен и принимает запросы.
3. Для нужной возможности настроен соответствующий провайдер: изолированная среда, векторные представления, поиск или генерация изображений.
4. У пользователя есть права на файл, коллекцию или другой ресурс.
5. Веб-интерфейс обращается к правильному адресу `/api`.
