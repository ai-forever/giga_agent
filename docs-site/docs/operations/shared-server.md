# Совместный сервер

Эта страница — краткий список проверок перед тем, как открыть локально запущенный GigaAgent коллегам. Рекомендации рассчитаны на демонстрационный или небольшой внутренний запуск.

## Минимальные меры безопасности

Перед публикацией адреса сервера:

1. Задайте длинный случайный секретный ключ.
2. Смените начальный пароль администратора.
3. Не используйте демонстрационный пароль `giga_agent_admin` для общего доступа.
4. Проверьте, кто имеет права администратора.
5. Не включайте инструменты выполнения кода для недоверенных пользователей.
6. Не публикуйте ключи провайдеров в тексте, снимках экрана и журналах.

Пример явной настройки секретного ключа для общего сервера:

```bash
export GIGA_AGENT_SECRET_KEY="<длинное-случайное-значение>"
```

Сгенерируйте значение в своей системе управления секретами или другим принятым в вашей инфраструктуре способом. Не используйте короткие, словарные или демонстрационные значения.

## Адрес и доступ

Для демонстрации коллегам нужен внешний адрес. Варианты:

| Вариант | Когда подходит | Важное ограничение |
|---|---|---|
| Внутренняя сеть или VPN | Коллеги в той же сети | Проверьте межсетевые правила и порт. |
| Временный туннель | Быстрая демонстрация | Адрес временный; не используйте для постоянной работы. |
| Обратный прокси с HTTPS | Более стабильный общий доступ | Требует настройки домена, TLS и ограничений доступа. |

Если используете временный туннель, не оставляйте его включённым после демонстрации.

## Что проверить до отправки ссылки

- Веб-интерфейс открывается по внешнему адресу.
- Вход работает под отдельной учётной записью, а не под вашим администратором.
- Языковая модель настроена и отвечает на короткий проверочный запрос.
- В интерфейсе нет видимых секретов.
- RAG-коллекции и файлы не содержат лишних данных.
- Изолированная среда выключена или ограничена, если пользователям не нужно выполнять код.

## Права пользователей

Для коллег лучше создать отдельные учётные записи. Не передавайте общий пароль администратора. Если нужно показать только чат, не выдавайте административные права.

При работе с коллекциями, файлами и провайдерами учитывайте права на ресурсы: пользователь должен видеть только те данные и настройки, которые нужны для демонстрации.

Подключения внешних сервисов через [каталог коннекторов](../user-guide/connectors.md) личные: токены OAuth хранятся за пользователем, и коллеги не получают доступ к чужой почте или файлам. Общими остаются данные OAuth-приложения Яндекса и боты каналов; помните, что в [канале Telegram](../user-guide/channels.md) агент действует без подтверждений вызовов, поэтому одобряйте контакты осмотрительно.

## Инструменты выполнения кода

Выполнение Python и команд — повышенный риск. Для демонстрации включайте эти возможности только если они действительно нужны.

Если изолированная среда использует Docker или доступ к файловой системе, проверьте:

- какие каталоги доступны;
- может ли пользователь запускать команды;
- какие ограничения памяти и процессов заданы;
- нет ли доступа к секретам хоста.

## После демонстрации

1. Остановите временный туннель или закройте внешний доступ.
2. Отзовите временные ключи провайдеров, если они использовались.
3. Удалите временные файлы и коллекции с чувствительными данными.
4. Проверьте журналы на случай случайной публикации секретов.
