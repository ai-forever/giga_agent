# Модули

:::info[Документация текущего состояния]
Эта страница описывает текущую ветку `main` репозитория GigaAgent. Для стабильной документации PyPI-пакета `giga-agent==0.1.9` выберите версию **0.1.9 (PyPI)** в переключателе версий.
:::

Модуль — единица расширения GigaAgent. Он может добавлять маршруты, модели базы данных, миграции, инструменты, системные инструкции, секреты, промежуточные обработчики, подграфы и обработчики запуска.

Эта страница описывает стандартного агента из текущей ветки `main`. Для стабильного набора модулей PyPI-пакета `giga-agent==0.1.9` используйте версию документации **0.1.9 (PyPI)**.

## Контракт BaseModule

Основные поля и методы:

- `id` — уникальный идентификатор модуля;
- `label`, `description`, `icon` — сведения для интерфейса;
- `get_api_router()` — маршруты FastAPI;
- `get_models()` — модели SQLAlchemy для миграций;
- `_get_tools()` / `get_tools()` — инструменты модуля;
- `get_instructions()` — добавления к системной инструкции;
- `extend_task()` — расширение пользовательской задачи перед запуском;
- `get_secrets()` — сведения о нужных секретах;
- `get_middleware()` — промежуточные обработчики агента;
- `get_subgraphs()` — точки входа подграфов LangGraph;
- `is_enabled()` — доступность модуля для пользователя;
- `on_startup()` — обработчик запуска.

Если у модуля непустой `label`, обёртка `get_tools()` помечает пользовательские инструменты через `extras["module_id"]`, чтобы граф мог фильтровать инструменты отключённых модулей.

## Активные модули текущей ветки main

`giga_agent dev` в текущем репозитории загружает 16 модулей:

1. `AuthModule` — авторизация, пользователи и токены.
2. `ReplModule` — инструменты выполнения кода через изолированную среду.
3. `ImageModule` — генерация изображений.
4. `AnalyzeImagesModule` — анализ изображений.
5. `IOModule` — чтение, запись, редактирование и удаление файлов через инструменты агента.
6. `ProjectsModule` — [проекты](../user-guide/projects.md): CRUD-маршруты и подстановка инструкций проекта в системный промпт.
7. `ScraperModule` — чтение веб-страниц.
8. `SearchModule` — поиск.
9. `RagModule` — коллекции документов и поиск по ним.
10. `MemoryModule` — долговременная память и поиск по записям памяти.
11. `SkillsModule` — пользовательские навыки агента и чтение манифестов навыков.
12. `GitHubModule` — интеграция с GitHub.
13. `VKModule` — интеграция с VK.
14. `WeatherModule` — прогноз погоды.
15. `DeepResearchModule` — глубокое исследование: план, поиск, чтение и отчёт с источниками.
16. `SubAgentLegacyModule` — субагенты совместимости и их подграфы.

## Маршруты модулей

Если `get_api_router()` возвращает маршрутизатор, `BaseAgent` монтирует его под:

```text
{GIGA_AGENT_PREFIX_API}/{module.id}
```

При стандартном префиксе внутри приложения это `/agent/{module.id}`. При запуске через `giga_agent dev` внешний путь обычно:

```text
/api/agent/{module.id}
```

Примеры:

- `/api/agent/auth/token`;
- `/api/agent/rag/collections`;
- `/api/agent/memory/...`;
- `/api/agent/skills/...`.

Точный набор маршрутов зависит от того, какие модули возвращают `get_api_router()`, а набор инструментов — от настроенных провайдеров, секретов и прав пользователя.
