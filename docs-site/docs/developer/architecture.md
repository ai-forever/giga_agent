# Архитектура

GigaAgent состоит из серверной части на FastAPI, графа выполнения LangGraph, модульной системы и встроенного веб-интерфейса React.

## Слои

```text
Браузер и веб-интерфейс
  ├─ страница: /
  ├─ рабочая конфигурация: /app-config.js
  └─ внешний префикс программного интерфейса: /api
Сервер разработки LangGraph (`giga_agent dev`)
  ├─ маршруты LangGraph: /api/...
  └─ маршруты GigaAgent: /api/agent/...
Приложение GigaAgent на FastAPI
  ├─ внутренний префикс: /agent
  ├─ основные маршруты: /agent/files, /agent/connectors, /agent/llms, ...
  ├─ маршруты модулей: /agent/{module.id}/...
  └─ BaseAgent + BaseModule + граф LangGraph
Провайдеры
  ├─ языковая модель и векторные представления
  ├─ изолированная среда
  ├─ поиск
  └─ генерация изображений
```

## Жизненный цикл BaseAgent

`BaseAgent`:

1. Создаёт приложение FastAPI с обработчиками запуска и остановки.
2. Проверяет `GIGA_AGENT_SECRET_KEY`.
3. Подключает основные маршруты с префиксом `GIGA_AGENT_PREFIX_API` (`/agent` по умолчанию).
4. Собирает модули из `get_modules()` и из переданного списка `modules`.
5. Проверяет уникальность `module.id`.
6. Подключает маршруты модулей по пути `/agent/{module.id}`.
7. Собирает промежуточные обработчики модулей и системные обработчики.
8. Создаёт граф выполнения через `create_graph()`.
9. Запускает миграции, обработчики старта, управление каналами, планировщик задач по расписанию и очистку изолированных сред.

## Выполнение графа

`create_graph()` отвечает за:

- выбор провайдеров через слой разрешения выполнения;
- сбор инструментов агента и инструментов провайдеров;
- добавление MCP-инструментов из состояния диалога;
- привязку инструментов к выбранной языковой модели;
- цикл “модель → инструмент → модель”;
- защиту от повторяющихся циклов;
- промежуточные обработчики и обратные вызовы.

Набор конкретных инструментов зависит от пользователя, настроенных провайдеров, секретов и отключённых модулей.

## Графы и подграфы

По умолчанию `giga_agent dev` использует путь:

```text
giga_agent.agents.run:graph:app
```

Регистрируются основной граф `giga_agent`, подграф `deep_research` из `DeepResearchModule` и подграфы субагентов совместимости: `landing`, `presentation`, `meme`, `lean_canvas`, `podcast`.

## Подключение внешних сервисов

Внешние сервисы двух видов собраны в едином каталоге подключений веб-интерфейса: серверы MCP из `modules/mcp/catalog.json` и модули-интеграции из пакета `modules/integrations/` (Яндекс.Почта, Яндекс.Календарь, Яндекс.Диск, VK). Модуль-интеграция несёт собственную авторизацию OAuth (`auth.py`, `provider.py`) с автоматическим обновлением токена. Реестр `core/integrations/registry.py` разрешает поставщиков по загруженным модулям агента; агент регистрируется в реестре при запуске через `set_current_agent()`.

## Виджеты в интерфейсе

Часть инструментов возвращает структурированный результат, который веб-интерфейс показывает интерактивным виджетом: входящие письма, календарь, обозреватель файлов Яндекс.Диска. Соответствие «инструмент → виджет» задаёт реестр `front/src/components/widgets/registry.ts`; общие элементы виджетов лежат в `front/src/components/widgets/kit/`. Серверная сторона помечает такие результаты через `modules/integrations/widget_hint.py`, чтобы агент не пересказывал содержимое виджета текстом.

## Внутренние и внешние маршруты

Внутри приложения FastAPI маршруты начинаются с `/agent`. При запуске через `giga_agent dev` внешний префикс — `/api`, поэтому из браузера чаще используются пути `/api/agent/...`.

| Назначение | Внутренний путь | Внешний путь при `giga_agent dev` |
|---|---|---|
| Получить токен | `/agent/auth/token` | `/api/agent/auth/token` |
| Файлы | `/agent/files` | `/api/agent/files` |
| Коллекции RAG | `/agent/rag/collections` | `/api/agent/rag/collections` |
| Память | `/agent/memory/...` | `/api/agent/memory/...` |
| Навыки агента | `/agent/skills/...` | `/api/agent/skills/...` |

## Связь с веб-интерфейсом

Веб-интерфейс читает `/app-config.js`. Обычная конфигурация:

```json
{
  "basePath": "/",
  "apiBasePath": "/api",
  "apiAgentBasePath": "/api/agent"
}
```

Это позволяет размещать интерфейс и программный интерфейс под разными префиксами без пересборки клиента.
