# Инструменты

Инструменты в GigaAgent появляются из нескольких источников: базовый агент, активные модули, провайдеры выполнения, изолированные среды и MCP-инструменты из состояния диалога.

## Определение инструмента

Чаще всего инструмент — это функция с декоратором `@tool` из `langchain_core.tools`. Но одного декоратора недостаточно: функция должна попасть в список инструментов, который собирает агент.

Типичный модуль:

```python
class MyModule(BaseModule):
    id = "my_module"
    label = "My module"

    async def _get_tools(self, user, agent, *, config=None, **kwargs):
        return [my_tool]
```

## Сборка списка инструментов

1. `BaseAgent.get_tools()` собирает базовые инструменты и инструменты модулей.
2. Обёртка модуля помечает пользовательские инструменты через `module_id`.
3. `graph_factory.py` добавляет служебные инструменты, например `think` и `multi_tool_use`, если они доступны.
4. Провайдеры выполнения могут добавить свои инструменты.
5. MCP-инструменты из состояния диалога преобразуются и добавляются отдельно.
6. Итоговый список передаётся выбранной языковой модели.

## Условная доступность

Документация должна описывать условия, а не обещать постоянную доступность.

Примеры:

- `get_documents` требует настройки RAG и векторных представлений;
- генерация изображений требует провайдера изображений;
- `analyze_image` требует модель с поддержкой изображений;
- `python`, `shell`, `await_shell` зависят от изолированной среды;
- GitHub, VK, погода и субагенты зависят от соответствующих секретов;
- MCP-инструменты доступны только если интерфейс передал их в состояние диалога.

## Отключённые модули

`BaseAgent` читает отключённые модули из:

1. `config.configurable.disabled_modules`;
2. `user.settings.disabledModules`.

Служебные модули без `label` не помечают свои инструменты как отключаемые пользователем.
