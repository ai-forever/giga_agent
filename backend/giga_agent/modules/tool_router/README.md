# tool_router — динамический выбор инструментов под GigaChat

GigaChat в режиме function-calling ограничивает блок определений функций
~**4096 токенами** (≈6–7 тулов). У агента инструментов ~20, поэтому перед
**каждым** вызовом модели роутер оставляет маленький релевантный поднабор.

Реализован как `AgentMiddleware.wrap_model_call` (модуль `ToolRouterModule`
регистрируется последним → его middleware — внутренний слой, видит финальный
запрос перед моделью). Подход детерминированный: правила + ключевые слова, без
дополнительных LLM-вызовов.

## Когда вообще срабатывает (gating)

Сужение включается **только если все условия** выполнены:

```python
_enabled()                        # флаг GIGA_AGENT_TOOL_ROUTER != off
and tools                         # тулы есть
and _is_gigachat(request.model)   # модель именно GigaChat
and _estimate(tools) > _BUDGET    # набор НЕ влезает в бюджет
```

Иначе — **прозрачный pass-through**. Для других провайдеров (OpenAI/Anthropic),
служебных вызовов без тулов и «уже влезающих» запросов поведение не меняется.

## Оценка бюджета (`_estimate`)

Токены блока функций оцениваются по откалиброванной формуле (замеры: 6 тулов
проходят, 7 — нет):

```
токены_тула ≈ len(json_схемы) / 2.6  +  370    # 370 — фикс. оверхед GigaChat/функция
```

Цель — держать сумму ≤ `_BUDGET_TOKENS` (по умолчанию 3800, запас под 4096).
Настраивается env: `GIGA_AGENT_TOOL_ROUTER_BUDGET`.

## Конвейер отбора (`_select`)

Собираем `keep` (что оставляем) и `ordered` (очередь кандидатов на дозаполнение):

1. **Костяк — всегда, не выкидывается** (`CORE_TOOL_NAMES`):
   `think`, `multi_tool_use` (спец-тулы GigaChat), `request_tools` (escape-hatch).
1b. **Незавершённые `tool_calls`** последнего хода — остаются (иначе рвётся цепочка).
2. **Operation-aware буст** (`TOOL_KEYWORDS`): тул, чьи точечные ключевые слова
   совпали с текстом запроса, идёт **первым** в очередь
   (`"удали"`→`disk_delete`, `"переведи задачу"`→`tracker_transition`).
3. **Доменные тулсеты** (`RULES`): по словам домена («диск/файл», «трекер/задач»)
   в очередь добавляются все тулы домена (по префиксу `disk_` / `tracker_`).
4. **Общий приоритет** (`DEFAULT_PRIORITY`) + всё остальное хвостом.

**Жадная упаковка:** идём по `ordered`, добавляем тул, пока сумма ≤ бюджета.
Костяк (3 тула) уже внутри → под домен реально остаётся ~3 слота.

Итог логируется: `ToolRouter: kept … dropped …`.

## Применение результата

Тулы байндятся в модель **до** middleware, а исполнитель игнорирует
`request.tools`. Поэтому роутер **пересобирает модель**:

```python
base = _unwrap(request.model)              # развернуть до базовой GigaChat
new_model = base.bind_tools(selected, ...) # ребайнд поднабора
req = request.override(model=new_model, tools=selected)
```

При любой ошибке ребайнда — pass-through исходного запроса (поток не ломается).

## Предохранители

1. **Loop-guard** (до отбора): 2 подряд хода с одним `request_tools` → обрыв +
   `system_notice` с подсказкой, какой модуль/секрет подключить. Защита от
   бесконечного цикла, когда нужного тула нет (выключен модуль / галлюцинация).
2. **Overflow** (после отбора): даже костяк не влезает → `system_notice` вместо 413.
3. **Limit-catch** (вокруг вызова): пойманный 413 от GigaChat → внятный
   `system_notice` вместо голой ошибки.

Все три помечаются `additional_kwargs={"kind": "system_notice"}` — фронт рисует
их отдельным серым info-баблом.

## Escape-механика (`request_tools`)

`request_tools` не подгружает тулы напрямую — он **фиксирует намерение в
истории**. На следующем ходу `_select` снова читает весь текст диалога (включая
аргументы `request_tools`) и буст/правила подтягивают нужный тулсет. «Динамика» =
пересчёт `_select` на каждом ходу по накопленному контексту.

## Свойства и границы

- **Стикинесс «бесплатно»:** `_select` смотрит на весь текст диалога, а не только
  последнее сообщение — раз упомянул «диск», disk-тулы держатся весь тред.
- **Кэш GigaChat:** набор стабилен, пока не меняется намерение → prompt-кэш не
  бьётся зря.
- **Поверх `disabled_modules`:** роутер сужает уже внутри включённых модулей.
- **Жёсткий предел:** ~3 слота под домен на ход. Несколько операций разных
  доменов в одном ходу не влезут — частично закрывается escape-hatch'ем,
  полноценно — консолидацией тулов (один `disk(action=…)` вместо N atomic).

## Конфигурация

| Env | По умолчанию | Назначение |
|-----|--------------|------------|
| `GIGA_AGENT_TOOL_ROUTER` | `on` | `off`/`0`/`false` → полностью выключить роутер |
| `GIGA_AGENT_TOOL_ROUTER_BUDGET` | `3800` | целевой потолок токенов блока функций |

## Как добавить домен (например новый модуль интеграции)

1. В `rules.py` → `RULES`: добавить `ToolsetRule(name, keywords, tools=("prefix_",))`.
2. В `rules.py` → `TOOL_KEYWORDS`: точечные слова под каждую операцию нового домена.
3. (Опц.) `_MODULE_HINTS` в `middleware.py` — подсказка для loop-guard, если домен
   запрошен, но модуль не подключён.
